# 生活费小账本

一个为大学生设计的生活费记账网页工具。它没有后端、没有数据库、不需要注册，打开浏览器就能使用，用来回答两个问题：这个月钱花到了哪里，手上还剩多少钱。

工具会记录每一笔支出和每月生活费到账，自动计算可用余额，并按“生活费周期”展示支出分类排行和账单明细。所有数据只保存在使用者自己的浏览器里。

## 功能特性

- 快速记账：金额、分类、日期、备注一次完成，支持支出和生活费到账两种记录。
- 收支看板：展示当前可用余额、本周期生活费、本周期已花三个核心数字。
- 分类排行：按分类统计本周期支出金额和占比，一眼看出钱主要花在哪里。
- 账单明细：记录按日期倒序分组，同一天自动合计，可点击编辑或删除。
- 生活费周期：默认从每月 1 日开始统计，也支持设置为每月 1-28 日中的任意一天。
- 学生分类：内置餐饮、交通、学习、购物、娱乐、日用、校园、其他 8 个分类。
- 自定义分类：可以新增自己的分类；删除已使用的自定义分类时，历史记录会自动归入“其他”。
- 完全本地：数据保存在当前浏览器的 localStorage，不联网、不上传、不需要账号。
- 数据备份：支持一键导出 JSON 备份，也可以导入备份文件恢复全部账本。
- 响应式页面：手机和电脑浏览器都可以正常使用。

## 使用方法

### 方法一：直接打开网页

把项目下载到本地后，用浏览器打开项目根目录下的 `index.html` 即可。

使用者不需要安装 Node.js，也不需要运行任何命令。

### 方法二：通过 GitHub Pages 在线使用

项目没有构建步骤，把仓库推送到 GitHub 后，可以在仓库设置里开启 GitHub Pages：

1. 打开 GitHub 仓库的 `Settings`。
2. 进入 `Pages`。
3. 在 `Build and deployment` 中选择 `Deploy from a branch`。
4. 分支选择 `main`，目录选择 `/ (root)`，然后保存。
5. 几分钟后，页面会显示一个类似 `https://你的用户名.github.io/仓库名/` 的在线地址。

通过 GitHub Pages 使用时，每位访问者的数据仍然只保存在各自的浏览器里，页面不会把账单上传到任何服务器。

## 第一次使用

第一次打开页面时，会先进入初始化设置：

1. **目前手上大约还有多少钱**
   建议把微信、支付宝、银行卡和现金里的钱加起来填写，作为账本的初始余额。
   如果暂时不清楚，也可以填 `0`，之后在“设置”中随时修改。

2. **生活费周期从每月几号开始**
   默认是每月 1 日。如果你的生活费不是 1 日到账，可以改成对应日期，页面会按新的周期重新划分月份。

点击“开始记账”后，就会进入首页看板。

## 记录一笔支出

1. 点击页面右上角的“记一笔”。
2. 确认类型为“支出”。
3. 输入金额，例如 `25.50`。
4. 选择一个分类，例如“餐饮”。
5. 备注为选填，可以写“食堂午饭”“宿舍楼下奶茶”等信息。
6. 日期默认是今天，也可以改成过去的日期，但不能填写未来日期。
7. 点击“保存”。

保存后，当前可用余额、本周期已花、分类排行和账单列表会同步更新。

## 记录生活费到账

1. 点击“记一笔”。
2. 把类型切换为“生活费到账”。
3. 输入本月收到的生活费金额。
4. 备注选填，可以写“九月生活费”。
5. 点击“保存”。

生活费到账会加入“本周期生活费”，并直接累加到“当前可用余额”中。

## 查看账单和看板

首页从上到下包含三部分：

### 1. 核心数字

- **当前可用余额**：初始余额 + 所有生活费到账 - 所有支出，跨周期持续累加，每月不会重置。
- **本周期生活费**：当前所选周期内所有生活费到账之和。
- **本周期已花**：当前所选周期内所有支出之和。

### 2. 分类排行

展示当前周期内每个分类的支出金额和占比，按金额从高到低排列。

### 3. 账单明细

账单按日期倒序展示，同一天的记录会合并显示。支出显示为负金额，生活费到账显示为正金额。

点击任意一条记录可以编辑金额、分类、日期或备注；编辑窗口中也提供了“删除这条记录”入口。

## 切换生活费周期

首页顶部的左右箭头可以切换上一个周期和下一个周期，默认停留在当前周期。

例如，如果周期起始日设置为每月 5 日：

- 2026-09-05 到 2026-10-04 属于同一周期。
- 2026-09-04 属于上一个周期。
- 2026-09-05 属于新的一个周期。

切换到历史周期后，看板和账单只显示那个周期的数据，不会影响“当前可用余额”。

## 设置页

点击页面右上角的设置图标进入设置页。

### 初始总余额

修改账本开始时的总余额。这个值会影响所有后续的余额计算，应尽量与第一次设置时保持一致的口径。

### 生活费周期

把起始日改为每月 1-28 日中的任意一天。修改后，当前看板会自动跳转到新的当前周期。

### 分类管理

- 内置分类不能删除。
- 可以新增自定义分类，例如“租房”“医疗”“游戏充值”等。
- 删除自定义分类前需要确认。
- 如果该分类已经用于记录，删除后这些记录会自动归入“其他”，不会直接丢失账单。

### 数据备份

- “导出备份”会下载一个包含全部分类、设置、初始余额和账单记录的 JSON 文件。
- “导入备份”会覆盖当前浏览器里的账本，导入前会再次确认。

## 数据存储与隐私

本项目是纯前端网页，不含服务器代码。它不会请求任何外部接口，也不会把账单上传到 GitHub、浏览器服务器或其他地方。

需要注意：

- 数据保存在“当前浏览器 + 当前设备”的 localStorage 中。
- 换浏览器、换电脑、使用隐私模式或清除浏览器数据后，数据不会自动同步。
- 如果需要在另一台设备继续使用，请先导出备份，再在新设备中导入。
- 页面显示的余额是“手动记账的结果”，不是微信、支付宝或银行的官方余额。漏记、重复记录或初始余额不准确都会影响余额。
- 如果多人共用同一台电脑和同一个浏览器资料，理论上其他人也可能打开页面看到账本。涉及隐私时建议不要共用浏览器账号，或在使用后手动清除数据。

## 常见问题

### 打开页面后是空的，账本不见了？

可能原因包括：更换了浏览器、清理过浏览器数据、使用了无痕模式，或直接删除了 localStorage。请确认正在使用原来的浏览器。账本没有云端副本，养成定期导出备份的习惯会更安全。

### 余额和微信/支付宝里的钱对不上？

这个工具不会读取微信、支付宝或银行账单。如果有些支出没有记录、初始余额填得不准确，或曾经清理过浏览器数据，余额就会和真实剩余金额不一致。可以逐笔核对账单，或在设置中修改初始余额来修正整体差额。

### 不小心删错了一条记录怎么办？

如果已经导出了备份，可以导入删除前生成的 JSON 备份恢复。如果没有备份，删除操作无法自动撤销。

### 可以同时记微信、支付宝和现金的余额吗？

第一版采用“单一总账本”设计，不区分支付渠道。所有渠道的钱放在同一个账本中计算，适合快速记账。如果你需要分别统计每个支付渠道的余额，属于后续版本功能。

## 本地开发与测试

运行测试需要 Node.js 18 或更高版本，但普通使用者不需要安装。

```powershell
npm test
```

测试覆盖：

- 默认周期与自定义周期的边界计算。
- 余额和周期汇总是否正确。
- 数据导入时的标准化与修复。
- 上一周期/下一周期切换是否正确。
